# بررسی نسخه وب IMEI — ۱۴۰۵/۰۷/۲۴ (۲۰۲۶/۱۰/۱۶)

## محدوده بررسی و حدود قطعیت

نشانی: `https://github.com/hmdnaeimi/imei`؛ شاخه `main`، در زمان بررسی یک Commit قابل مشاهده. فایل‌های متنیِ قابل مشاهده از صفحات خام GitHub خوانده شدند: `index.php`، `api.php`، `lib.php`، `schema.sql`، `install.php`، `install-core.php`، `logout.php` و `assets/app.js` / `assets/app.css`. `app.js` بسته فشرده/minified مربوط به React است و مشاهده خطوط خام آن جایگزین اجرای واقعی و حسابرسی همه اجزای رابط نمی‌شود. **کلون کامل با Git و فهرست قطعی فایل‌های asset به‌علت قطع DNS در محیط اجرای حاضر ممکن نشد**؛ بنابر این «بررسی کامل همه فایل‌ها» هنوز تأیید نشده است. تصویر و CSS مرجع کاربر برای طراحی استفاده شدند، نه برای اثبات قابلیت قدیمی.

## آنچه مستقیماً در بک‌اند تأیید شد

- `schema.sql`: جدول‌های `app_users`، `app_phones`، `app_aliases`، `app_trades`، `app_audit`، `app_user_events`، `app_login_limits`، `app_imports`؛ کلید اصلی IMEI در `app_aliases.imei` یکتا، `phone_id, slot` نیز یکتاست. شناسه دوم قابل خالی‌بودن است. معامله FK به گوشی دارد. `deleted_at` حذف منطقی، `version` کنترل نسخه و snapshot تاریخچه دارد.
- `lib.php:24–34`: IMEI اول اجباری و دوم اختیاری، **فقط ۱۵ رقم بودن** بررسی می‌شود و **Luhn وجود ندارد**. کد ملی در نسخه اصلی **فقط ۱۰ رقم** بررسی می‌شود، نه رقم کنترلی. تماس اختیاری با الگوی ۷ تا ۱۵ رقم، پنج فیلد متنی اجباری و سقف ۱۰۰ نویسه، یادداشت ۵۰۰۰ نویسه، `kind=buy/sell`، `condition=new/used`، `registration=company/passenger/none`. تاریخ **شمسی به‌شکل YYYY/MM/DD** ذخیره می‌شود و کبیسه بررسی می‌شود.
- `lib.php:40–43`: گوشی با IMEI مشترک پیدا یا ساخته می‌شود؛ شماره دوم در صورت خالی بودن Slot 2 می‌تواند بعداً به همان گوشی اضافه شود؛ دو IMEI متصل به دو گوشی متفاوت رد می‌شوند. هر ثبت معامله تاریخچه `create` ذخیره می‌کند. در این منطق **محدودیت تکرار فروش برای موجودی/عدم موجودی دیده نشد**.
- `api.php`: GET فهرست معاملات فعال/حذف‌شده، سابقه هر معامله، لیست همکاران؛ POST معامله جدید، ورود پشتیبان JSON و افزودن کاربر؛ PATCH ویرایش، حذف منطقی و بازیابی؛ مدیر تنها نقش مجاز برای حذف، بازیابی، مدیریت کاربر و ورود پشتیبان است؛ برای ویرایش نسخه رکورد بررسی می‌شود. IMEI روی ویرایش معامله از گوشی اصلی بازخوانی و غیرقابل‌تغییر است. تاریخچه از snapshot قبلی هر تغییر ذخیره می‌شود.
- `api.php:22–30`: واردکردن حداکثر **۵۰۰۰** معامله از JSON، رد کردن تکرار بر اساس `id`/مبدأ، افزودن موارد دیگر در تراکنش. بنابر کد UI داخل `assets/app.js`، فایل JSON نسخه قبلی دارای آرایه `transactions` است و محدودیت فایل ۱۵ مگابایت در UI اعمال می‌شود.
- `index.php`: احراز هویت با نام کاربری/رمز و Session سمت سرور، پنل SPA مبتنی بر React، ۵ تلاش در ۱۵ دقیقه، خروج. `install-core.php`: حساب مدیر در زمان نصب، دیتابیس جداگانه MySQL و تعریف نام/نام کاربری/ایمیل/رمز مدیر؛ نقش همکار `staff`.
- `app_users`: `role` با مقدارهای `admin` و `staff`، `active`، `session_version`، هش رمز. مدیریت فعال/غیرفعال و تغییر رمز همکار در `api.php` وجود دارد؛ تغییر رمز مدیر در این API عمداً منع شده است.
- نصب وب PHP >=8.3 و MySQL بوده است. اجزای احراز هویت، API و MySQL **نباید** به اپ مستقل منتقل شوند.

## مواردی که از نسخه اصلی تأیید نشده‌اند و ادعا نمی‌شوند

اسکن دوربین داخلی، شماره سریال و تصاویر دستگاه، قیمت یا سود مالی، اعتبارسنجی Luhn، اعتبارسنجی محاسباتی کد ملی، قفل بیومتریک، SQLCipher و همگام‌سازی ابری، سیستم گردش/کنترل موجودی، مدیریت مدل/رنگ پیش‌فرض، گزارش مالی و PDF. به‌جز عناصر محدود موجود در باندل JS، حضور کامل همه امکانات UI نیازمند بررسی/اجرای نسخه وب است. **شبیه‌بودن تصویر مرجع به یک قابلیت، مدرک وجود آن در نسخه اصلی نیست.**

## تفاوت‌های عمدی نسخه اندروید

نسخه مستقل داده اصلی را به Room خصوصی منتقل می‌کند؛ تاریخ را ISO `yyyy-MM-dd` می‌گذارد و با ICU به شمسی نمایش می‌دهد؛ IMEI را علاوه بر طول با Luhn و کد ملی را با رقم کنترلی بررسی می‌کند؛ ورود پشتیبان قابل حمل به‌صورت AES-256-GCM جایگزین جریان فایل JSON بدون رمز وب است و همچنین مسیر جدا برای ورود JSON قدیمی دارد. کاربران محلی از حساب آنلاین فعلی مستقل‌اند. هش رمز با PBKDF2 و نمک منحصربه‌فرد نگهداری می‌شود.

## هشدار مهم امنیتی درباره مخزن مرجع

در فهرست مخزن عمومی فایل‌های `config.php` و `install-secret.php` دیده می‌شوند. اگر حاوی اطلاعات عملیاتی/رمز فعال باشند، **انتشار عمومی آن‌ها خطرناک است**. بدون نقل مقادیر، پیشنهاد می‌شود دسترسی‌ها، رمزهای بانک اطلاعاتی و کلید نصب بررسی/تعویض شوند و فایل‌های حساس از تاریخچه عمومی Git و استقرار بیرونی پاک‌سازی شوند. این فایل‌ها در پروژه Android وارد نشده‌اند.
