# معماری، مدل داده و امنیت

## معماری اجرایی نوشته‌شده

`MainActivity` → Compose/Navigation/`MainViewModel` → `TradeRepository` / `AuthService` / `PortableBackup` / `LegacyJsonImporter` → DAO → `LocalDb` (Room/SQLite). منطق مستقل از UI در `domain/Rules.kt` و `domain/BarcodeParser.kt` قرار دارد. `Flow` برای ردیف‌ها/شمارنده و `StateFlow` برای فرم و عملیات استفاده می‌شود. وابستگی‌تزریقی با Composition Root ساده در `ImeiApplication` انجام شده است؛ به‌دلیل یک ماژول و تعداد محدود سرویس‌ها Hilt فعلاً افزوده نشده است. این نسخه پایه‌ای برای Clean Architecture است؛ تفکیک بیشتر در ماژول‌های domain/data/ui پیش از نسخه بزرگ توصیه می‌شود.

## مدل Room، نسخه ۱

- `phones(id PK,createdAt)` — یک گوشی ممکن است معاملات متعدد داشته باشد؛ خود گوشی بدون تراکنش موجودی/قیمت ندارد.
- `aliases(imei PK,phoneId FK -> phones,slot)` — شرط `UNIQUE(phoneId,slot)` و `PRIMARY KEY(imei)` جلوی تکرار IMEI را **در خود DB** می‌گیرد. IMEI2 اختیاری است و می‌تواند بعداً اضافه شود؛ هنگام معامله با گوشی شناخته‌شده هر یک از دو IMEI می‌تواند آن را شناسایی کند، ولی ترتیب اصلی slotها در جدول دستگاه ثابت می‌ماند؛ شناسه‌ها ۱۵رقمی Luhn اعتبارسنجی می‌شوند.
- `trades(id PK, phoneId FK, kind, dateIso, firstName, lastName, nationalId, contact, model, color, memory, condition, registration, notes, createdBy, createdName, updatedBy, updatedName, createdAt, updatedAt, deletedAt, version)` — اطلاعات شخص snapshot معامله است؛ کد ملی و تماس رشته‌اند، تاریخ معامله ISO، زمان ثبت/ویرایش epochMillis.
- `audit(id PK,tradeId FK,action,actorId,actorName,at,snapshot)` — snapshot با AES-GCM و Keystore داخلی رمز شده است.
- `users(id PK,username UNIQUE,email UNIQUE,name,role,active,hash,salt,failed,lockedUntil,sessionVersion)` — هیچ حساب/رمز اولیه‌ای در برنامه هاردکد نشده است.
- `user_events(id,userId,action,actorId,at)` — تغییر کاربران و رمز/فعال‌سازی.

مهاجرت: نسخه اول schema برابر ۱ است و **از نسخه قبلی Android مهاجرتی وجود ندارد**. Room با `exportSchema=true` و `room.schemaLocation` برای تولید فایل schema تنظیم شده است. مهاجرت `1→2` تا زمانی که نسخه ۲ تعریف نشود قابل نوشتن و آزمایش واقعی نیست. هیچ `fallbackToDestructiveMigration` استفاده نشده؛ انتشار نسخه بعدی بدون Migration باید مسدود شود.

## قواعد و تراکنش‌ها

`TradeRepository.create/edit/changeDeleted` و ورود/بازیابی گروهی با `withTransaction` اجرا می‌شوند. هر خطا درج گوشی، alias، معامله و audit را یک‌جا برمی‌گرداند. هنگام ثبت دوباره همان گوشی، معامله تازه مجاز است؛ شناسه جدید تنها اگر جایگاه دوم خالی باشد اضافه می‌شود. ترتیب شناسه‌های واردشده ممکن است با ترتیب ذخیره‌شده گوشی قبلی متفاوت باشد؛ شماره‌های اصلی دستگاه تغییر نمی‌کنند. دو شناسه متعلق به دو گوشی مختلف رد می‌شوند. در ویرایش، IMEI تغییر نمی‌کند (همان رفتار نسخه وب). حذف/بازیابی فقط مدیر با بررسی نسخه و حذف منطقی انجام می‌شود.

**هشدار درباره منطق وضعیت:** کد `lib.php` سایت گردش stock را تعیین نمی‌کند. جلوگیری از فروش بیش از موجودی و محاسبه سود/قیمت بدون نیازسنجی و مدل مالی واقعی به‌عنوان قابلیت موجود معرفی نشده‌اند.

## اعتبارسنجی

IMEI: ۱۵ رقم پس از تبدیل ارقام فارسی/عربی + Luhn. کد ملی: دقیقاً ۱۰ رقم با رقم کنترلی ایرانی؛ مقادیر تکراری یک‌رقمی رد می‌شوند. شماره تماس در صورت ورود رشته با قالب ایرانی متداول بررسی می‌شود. فیلدهای نام/نام خانوادگی/مدل/رنگ/حافظه خالی و رشته صرفاً فاصله رد می‌شوند. یادداشت حداکثر ۵۰۰۰ نویسه. قواعد در `domain` و هنگام ذخیره `Repository` مجدداً ارزیابی می‌شوند.

## تقویم

برای تبدیل از/به شمسی از `android.icu.util.Calendar.getInstance(ULocale("fa_IR@calendar=persian"))` روی API 26+ استفاده می‌شود؛ بازه picker ۱۳۰۰ تا ۱۵۰۰ است. تاریخ ISO مستقل از زمان epochMillis ثبت/ویرایش است. قبل از عرضه، آزمون دستگاه/منطقه‌زمانی و روزهای مرزی باید روی Android واقعی انجام شود.

## رمزنگاری، قفل و محدودیت‌های امنیتی

- قفل حساب محلی: PBKDF2-HMAC-SHA256 با ۳۱۰هزار دور، نمک تصادفی ۱۶بایتی مستقل برای هر کاربر، کلید خروجی ۲۵۶بیتی؛ ۵ تلاش شکست‌خورده → قفل ۱۵ دقیقه؛ `sessionVersion` برای باطل‌کردن نشست همکار. پردازش KDF روی Dispatcher پیش‌زمینه اجرا نمی‌شود. اگر برنامه بیش از ۵ دقیقه در پس‌زمینه باشد، هنگام بازگشت نشست به‌صورت خودکار قفل می‌شود؛ این رفتار برای استفاده از انتخابگر فایل هم صدق می‌کند. قفل دستی و قفل مجدد با خاتمه فرایند نیز فعال است. آزمون زمان‌سنج روی دستگاه باقی است.
- رکوردهای تاریخچه (`snapshot`) با AES-GCM و کلید AES Android Keystore رمز می‌شوند. از کلید Keystore نباید در فایل پشتیبان قابل حمل استفاده شود، بنابراین هنگام تهیه پشتیبان محتوای snapshot در حافظه رمزگشایی، با رمز گذرواژه پشتیبان رمز می‌شود و هنگام بازیابی زیر کلید دستگاه جدید مجدداً مهروموم می‌گردد.
- **کل پایگاه داده رمزگذاری نشده است.** SQLite داخل فضای خصوصی برنامه (`MODE_PRIVATE` سامانه) می‌ماند، اما روی دستگاه Rootشده یا هنگام تصاحب کامل دستگاه امنیت قطعی ندارد؛ سطح حفاظتی به مرور امنیتی بیشتر نیاز دارد.
- نسخه پشتیبان قابل حمل: Header ASCII `IMEI-LOCAL-BACKUP-1\n`، salt تصادفی ۱۶بایتی، IV تصادفی ۱۲بایتی، AES-256-GCM با tag ۱۲۸بیتی. کلید از پاسفریز حداقل ۱۲ نویسه با PBKDF2-HMAC-SHA256 ۳۱۰هزار دور مشتق می‌شود؛ header به‌عنوان AAD احراز می‌شود. payload JSON نسخه‌دار `schema=1` دارد. محدودیت فایل ورودی ~۱۵MB و محدودیت تعداد: ۵۰۰۰ گوشی/معامله، ۱۰هزار alias، ۳۰هزار audit. کلید رمز در نسخه پشتیبان وجود ندارد.
- بازیابی کامل: ابتدا نسخه/اصالت/رمز، ردیف‌ها و یکتایی IMEI و FKها اعتبارسنجی می‌شوند؛ پیش‌نمایش، سپس تأیید صریح حذف معاملات و جایگزینی؛ همه تغییرات داخل **یک تراکنش** است و حساب‌های محلی حذف نمی‌شوند.
- واردسازی legacy JSON: دریافت تنها از Storage Access Framework (بدون دسترسی عمومی حافظه)، حداکثر ۵۰۰۰ معامله و ۱۵MB؛ تطبیق IMEI/کد ملی قوی‌تر از نسخه وب؛ تکرار بر اساس ID رد می‌شود؛ درج افزایشی و یکپارچه در تراکنش است. داده قدیمی خودکار اصلاح نمی‌شود.
- `allowBackup=false`، حذف اینترنت در Manifest، `usesCleartextTraffic=false`، `FLAG_SECURE` برای جلوگیری از Screen Capture/نمای اخیر، عدم Log کردن شناسه/کد ملی و استفاده از Storage Access Framework.

## خطرهای باقیمانده

1. رمزنگاری تمام DB و تأیید مقاومت در برابر دستگاه آسیب‌پذیر/Root هنوز انجام نشده است.
2. متن JSON و کپی آن حین backup/restore در حافظه قرار دارد و باید تحت ارزیابی حافظه و heap بررسی شود. گذرواژه از Compose String گرفته می‌شود و پاک‌سازی قطعی حافظه JVM تضمین‌شده نیست.
3. اگر برنامه پاک شود، داده خصوصی/کلید Keystore از بین می‌رود؛ بدون پشتیبان مستقل رمزدار بازیابی ممکن نیست.
4. `FLAG_SECURE` محافظت مطلق در برابر همه ابزارهای تصویربرداری، بدافزار سیستم یا دستگاه Rootشده نیست.
5. پایش شبکه/مانیفست **پس از Build** ضروری است؛ حذف permission به‌تنهایی جایگزین تحلیل همه مجوزهای کتابخانه‌ها نیست.
6. تمام خطرها و خطاهای ورودی نسخه وب هنوز با اجرای واقعی UI باندل و داده واقعی آزمایش نشده‌اند.
